- **Library callers that hold a `PCB` across a working-directory change keep reading the loaded board's own project** (Issue #10743). `KiCadPCBExporter.apply_to()`, `relocate_pad_edge_vias()`, `BypassCapDistanceCheck`, the pour-stub proof (`prove_pour_stubs()` / `select_pour_stubs()`) and the design-decision helpers (`get_decisions()`, `record_decision()`, `get_decision_store()`, `save_decisions()`) resolved the `.kicad_pro` / `.kicad_dru`, schematic or decisions ledger beside the caller-visible relative `pcb.path`, so after a `chdir` they read whatever sat beside that name in the new directory -- the hazard #10683 closed for `DRCChecker`. They now use `PCB.source_path`, staying bound to the project the board was loaded from or last saved to. `pcb.path` is unchanged, a board built in memory keeps its defaults, and an explicit `clearance_rules`, `schematic_path` or `rule_files` still wins.
