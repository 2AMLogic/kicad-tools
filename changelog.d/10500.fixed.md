- **`kct parts alternatives` reports where each stock count comes from** (Issue #10500). The command reads the offline jlcparts catalog, but its JSON gave only a bare `stock` number for the source part and each candidate, and the text table headed that column `Stock`, so a BOM consumer could not tell a cached catalog count from verified inventory. Every JSON row now keeps its integer `stock` and adds the `inventory` object that `parts lookup` and `parts search` already emit. For a catalog row with no recorded observation time it reads `source: "offline_catalog"`, `observed_at: null` and `stock_verified: false`, with the local read time in `read_at`. The text column is now headed `Offline catalog stock`.
