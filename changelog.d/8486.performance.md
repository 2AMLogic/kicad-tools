- **`kct route` stops re-searching stalled unsealed nets at the full per-net cap every iteration** (Issue #8486).
  On a zero-overflow-stalled board the negotiated loop searched each still-unrouted net twice per
  iteration — the zero-overflow recovery and the targeted-ripup fallback — and neither search fed the
  #8486 known-failure back-off, so the reported narrow signal nets kept the full ~30 s cap each time
  and only one ever backed off. Both searches now run through the back-off wrapper, a copper-keyed
  streak survives foreign-copper churn and iterations the loop searched elsewhere, and every 3
  iterations a backed-off net is retried once at its full cap, so a corridor that genuinely opened is
  rediscovered in bounded time. Failed nets stay in the failed-nets report and the per-iteration
  known-fail seconds line now counts these searches.
