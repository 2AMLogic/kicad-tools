- **Per-call route traces now split each call's wall time into native search, Python fallback and other seconds**
  (Issue #8486). Records drained from `enable_per_call_timing` carry
  `native_search_seconds` (the fresh native searches), `python_fallback_seconds`
  (the Python fallback A*) and `other_seconds` (setup, stored-route sync and
  clearance-validation resumes), which sum to `elapsed`. A saved trace can now
  say where the time of a slow via-blocked or timed-out call went, instead of
  leaving it outside the recorded native searches. Purely observational: the
  produced copper is identical with tracing off and on.
