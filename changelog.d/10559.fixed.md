- **`kct pcb reinforce` names the malformed coordinate in a wire-list sidecar instead of raising a traceback** (Issue #10559).
  When a record in `<board>.reinforcement.json` holds a nested coordinate a writer cannot use -- an anchor, leg
  end, `polyline` point, stitching via or `copy_segments` endpoint that is not an object with numeric `x` and
  `y`, or a point list that is not an array -- every pass that reads the list as records exits 1 with
  `<sidecar>: wires[<i>].<field> is <type>, expected <shape>`, such as
  `wires[1].anchors[0] is a string, expected an object with numeric 'x' and 'y'` or
  `wires[0].leg_start has no 'y', expected a number`, where `<i>` is the entry's position in the file. The
  index names the entry before any sorting, so `--net` on another net refuses the same way. `--clear`,
  `--replace`, `--adopt`, `--list-wires` in text, a pass that records wires and `kct pcb center-on-sheet`
  before a nonzero move all refuse before writing either file; input and output boards and sidecars keep their
  bytes. Read-only consumers and `--list-wires --format json` still pass such a record through unchanged.
  `--list-wires` and `--adopt` now print the sidecar path once in that message, not twice.
