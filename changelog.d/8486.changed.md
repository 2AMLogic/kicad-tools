- **Per-call route traces now show how each Python fallback relates to earlier searches** (Issue #8486). With timing enabled, `request` identifies the first search from a pad, a repeat, or a changed request. Repeats include `grid` (changed or unchanged) and `prior_outcome`. Disabling timing clears this history. A skip before classification (native timeout, tuned iteration cap, repeated clearance failure, or missing Python grid) reports `request=unclassified` and omits `grid` and `prior_outcome`. Each record names the action taken. Searches that ran also report their outcome (`found`, `drained`, `deadline`, or `stopped`), elapsed seconds, and budget.
