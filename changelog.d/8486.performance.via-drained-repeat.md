- **`kct route` no longer re-runs the Python fallback for a pad pair whose search already drained after a via-blocked verdict** (Issue #8486). When the C++ search
  ends with `via_via_blocked` and the pure-Python A* then drains its open set for that pad-pair
  request, a later repeat of the same request re-ran the 10-100x slower search on every
  negotiated iteration -- on the reported board five calls on one pair spent 21.55 s of a
  60.00 s sample re-proving the same drain. The drained repeat is now skipped like the
  `no_path` case (issue #8370). The first attempt of every request, including a tree goal
  instead of the direct pad, keeps its full fallback budget, a search stopped by the wall-clock
  deadline records nothing, and ripping up the blocking copper recovers in the native search or
  through the per-net re-probe that resets the record.
