- **`kct export` now refills saved zones when it changes the rules they were filled under** (Issue #9987). The exporter writes the manufacturer `.kicad_dru` beside the source board before preflight and plotting, and since #8937 that block carries one zone-scoped clearance rule per pour -- but `kicad-cli` plots the copper saved in the board, so a pour filled before its rule existed shipped stale. On Board 06's nine-pair seed-42 recipe the export added five 0.30 mm zone rules and then plotted pours last filled at the fab floor: the Gerbers, the archived PCB and the `.kicad_dru` in the project ZIP disagreed, with 499 native clearance errors on the saved board and zero after a refill. Export now persists a native refill (`kicad-cli pcb drc --refill-zones --save-board`) at the point the final rules take effect, before any check, plot, archive or manifest hash reads the board, so the saved PCB, the project ZIP, the manifest and the plotted zones agree and saved and refilled native DRC give the same verdict. An unchanged-rule second export, a board whose fill already matches its rules, a dry run and a bundle with neither Gerbers nor a project ZIP trigger no refill; a named `--stackup-id` is bound to the bytes that ship. Tracks, vias, net assignments and caller-owned rules are untouched.
