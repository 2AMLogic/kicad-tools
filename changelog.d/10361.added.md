- **`path_ampacity` judges simultaneous currents on shared copper** (Issue #10361). The
  `current_paths.json` sidecar's object form accepts an optional `cases` list; each case names
  the declared paths active together with signed `current_a` contributions (relative to each
  path's source-to-sink direction) and an optional `pulse_overlap` (`coincident` / `disjoint`).
  Contributions add and cancel per physical track interval or series via transfer, so a shared
  feed is judged on its combined current and findings name the case, contributing paths, combined
  current and location. An unknown, repeated or ambiguous path reference, or an unresolved member,
  is an error and blocks a verdict on a partial total; two pulsed members with no declared overlap
  leave combined RMS/peak undetermined and say so. Without `cases` (and for legacy bare-list
  sidecars) every path is still checked independently. Combined fusing is not evaluated; fusing
  stays a per-path check.
